# M6 first run (#170)

The first training run with all M6 changes (spec #160: arm contact, termination penalty, deep targets, start-pose
table, contact point and compression metrics), judged against the M5 baseline (run 13, #39) and the success criteria
the user set in #170 before the run.

## Run

- `m6-first`, [ks9iqkbe](https://wandb.ai/ppetri-eth-z-rich/stem-manip/runs/ks9iqkbe), commit 1713c2f78dac
  (branch `feat/170-m6-first-run`), 2026-10-16.
- 4096 envs, 48 steps per env, 750 iterations, seed 42: the M5 baseline's settings (same samples per run; user,
  2026-10-16). PPO settings as committed (`agents/rsl_rl_ppo_cfg.py`; run 13's config).
- About 3.0 h (12:40–15:39), 12–20 s per iteration: the GPU was shared with another worktree's checks for part of the run.

## Observations

- **Tip-only pushing**: 90 % of the fork-contact episodes have their contact point in the top 4 segments (p10
  0.322 m on the table). The deep targets did not move the contact down the stem; ADR 0004's fallback (a penalty on
  contact with the top 4 segments) is the next step it names.
- **Arm contact with the mean action**: 10.1 % of the episodes end by arm contact with the mean action against 2.6 %
  in training (sampled actions). The same gap as M5's early terminations (11.1 % against about 2.5 %), larger; its
  cause is still unknown. From c_low (slot base 8 cm above the ground, beside the stem) it is 29.5 %.
- **Held-out start poses**: with one fixed arm pose the spawn event redraws stem positions that overlap the fork or
  the arm in that pose, so the stem positions differ from the table evaluation's; part of the `reached` gap may come
  from that, not from the start pose alone.
- **Compression (#82)**: the episodes' largest axial compression is 1.86 N on average at the end of training
  (0.40 N at iteration 83), the mean over an episode 0.39 N. Only episode means are logged; the evaluation does not
  record the compression. With tip-only pushing this data comes from pressing the tip, not from pushing inside the
  slot.

The user (2026-10-16): the stem is still pushed, not taken into the slot. From a low start the fork moves up and
again manipulates the stem very close to the tip, by pushing, not with the slot. This matches the contact point
(c_low: p10 0.253 m, median 0.349 m). The `approach` reward does not pull the fork up: it rewards the slot base's
distance to the whole stem centre line, not to the tip.

## Decisions

- The user, 2026-10-16: the criteria are missed and the stem is still pushed at the tip. ADR 0004's fallback (a
  penalty on contact with the top 4 segments) is not run as it stands: it would move the contact down the stem but
  not make the policy use the slot (it could push with a prong lower down). The approach to slot use is revisited in
  a grilling before the next run.
- Pending (user): the compression limit (#82) and the episode length; the compression data above comes from tip
  pressing.
