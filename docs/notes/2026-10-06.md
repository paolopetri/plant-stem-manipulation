# Later the same day — stage-1 environment, action and controller

## Done
- Branch `feat/push-position-env`: `StemManip-Push-Position-FR3-v0` registered (scene FR3 + fork_v2 + chain stem, tool-tip observation, reset to default, time out); launches, steps and resets with 4 envs, `isaaclab zero_agent` runs. `scripts/check_push_env.py`: shapes (4, 6) / (4, 3) and the fixed fork orientation (0.5 deg) pass; "follows the actions" fails (13 instead of 90 mm), see below.
- Bug found and fixed: the FR3 was a floating-base articulation (the USD's base joint attaches `fr3_link0` to the asset's root prim, which is not a rigid body). With more than one env the robots of envs 1+ were dragged towards env 0 and exploded (the contact check only uses one env). `fr3_cfg`: `fix_root_link=True`; the robot is now fixed-base (`is_fixed_base` True, no base columns in the Jacobian). `check_contact.py --test slot` re-run: all passed, same values.
- `mdp/__init__.py` uses `lazy_export()` with an `__init__.pyi` stub (as Isaac Lab's tasks): `from isaaclab.envs.mdp import *` loaded USD modules before the app started and Kit failed to start.
- Literature search on action spaces / controllers for sim-to-real and a sweep of Franka's Cartesian impedance law (`scripts/sweep_impedance.py`, 27 envs: 3 target variants x K_p 150/400/1000 N/m x 5/10/20 cm/s). Write-up with tables and references: `docs/overleaf_folder/open_questions/impedance_action_study.tex`. Main results: target relative to the measured position: the fork covers 1-4 of 10 cm; integrated target (PLAI): following error 7.1 / 4.3 / 2.4 mm at 5 cm/s for K_p 150 / 400 / 1000; with velocity feedforward 2.1 / 2.0 / 0.3 mm; contact force 0.8-1.4 N and curvature 2.0-3.2 1/m in all integrated cases.
- Found: the simulated FR3 has no reflected motor inertia; without it the impedance-controlled arm oscillates and presses the stem with 5 N instead of 0.85 N. The sweep adds it as joint armature (0.61 / 0.46 / 0.21 kg m^2 for joints 1-2 / 3-4 / 5-7, from the URDF).

## Decisions
- Stay in end-effector space for the action (user).
- The low-level controller must be the same in simulation and on the real FR3 (user: sim-to-real is the point of the project). Proposal: Franka's Cartesian impedance law with an integrated target; gains and speed to confirm (docs/TODO.md, M4). The IK + joint-PD action (Isaac Lab's `FRANKA_PANDA_HIGH_PD_CFG` gains, 0.2 s lag, not the real robot's behaviour) is not used.
- Start pose: fork horizontal, pointing forward, above and behind the stem area (user).
- The policy does not need the fork geometry as input: fork and orientation are fixed, so the tool-tip position fixes the whole fork; add the tool orientation once it becomes part of the action (stage 2).
- Reading for the topic (user asked for an overview): Aljalbout et al., The Reality Gap in Robotics (Annual Review of Control, Robotics, and Autonomous Systems, 2026, arXiv:2510.20808); for the action space Aljalbout et al., RA-L 2024 (arXiv:2312.03673).
