# 2026-10-05 — M1b: modular stem models

## Done
- Stem models selectable by name (`refactor/modular-stem-models`). `assets/stem/stem.yaml` now holds only the plant (length, diameter, base position, density, bend/twist modulus, damping time, damage limits); `assets/stem/cable/cable.yaml` holds the cable-only values (segment count, stretch/shear modulus, VBD solver settings). `stem_params(model)` merges both and refuses keys defined twice. Code: `src/stem_manip/assets/stem/` with `__init__.py` (`stem_params`, `stem_model(name)`, `STEM_MODELS` from the asset folders) and `cable.py` (the former `stem.py`, plus `physics_cfg()`). `check_stem.py --stem_model` (default `cable`); `sweep_stem_solver.py` stays cable-only.
- Verification: merged params identical to the old `stem.yaml`; `pytest` 23 passed; `check_stem.py --stem_model cable` gives the same values as on main in all 13 checks (push 10.2 / 10.26 mm, sag 15.78 mm, 4.67 Hz, damping ratio 0.063); `sweep_stem_solver.py --test push` 10.27 mm as before.

## Decisions
- Layout A: plant values once in `stem.yaml`, model values in `<model>/<model>.yaml` (folder per model, room for a generated USD of the chain); one module per model with the same function names, looked up by name; one `check_stem.py` for all models. The cable gets no further work in M1b beyond keeping it runnable for the comparison.
- Cable stretch/shear stay absolute values in Pa (no ratio rewrite). The plant has no shear or stretch value: it is treated as a thin rod, and in the `chain` model they are rigid by construction.
- The model contract is minimal for now (`stem_cfg`, `physics_cfg`, `fix_stem_base`); the stem-pose accessor and state writing get their shared form when `chain` exists.
